# 스토리 검토·두 가지 보기·다시보기 입력 템플릿

사용 목적: 검토한 줄거리와 세계선 관계를 보존하면서, 사용자가 보내는 방송 링크와
시각을 기존 장면에 연결한다. 실제 입력 전에는 시각·하이라이트·영상 URL을 만들지 않는다.
이 문서는 작성 양식이다. Elio의 story/source/media/connections 계약을 대체하지 않는다.
새 이야기에는 참고 URL을 받지 않아도 [공통 작성 기준](reading-views.md)을 적용한다.
인물 생애·회상 시간순·인과 지도 중 유용한 보기를 근거로 선택하며 단순한 이야기에 강제하지 않는다.

## 1. 출처를 읽고 본문을 검토한다

- [독자 문장과 편집 근거의 경계](reading-views.md#keep-editorial-work-in-the-evidence-record)를 적용한다.
  인용 조합·배치·수정 방법은 기존 근거·검토 기록에 남기고, 독자용 문장에는 장면의
  행동과 의미를 쓴다. 검토할 때 제목·요약·하이라이트·해설·사진 상세를 수정 이력을
  모르는 독자의 입장에서 읽는다. 필요한 발화 주체와 이야기의 불확실성은 보존한다.
- 별도 지시 없이도 [이름·레퍼런스 조사와 깊이 읽기 기준](reading-views.md#research-names-and-references-earn-the-deeper-reading)을 적용한다. 해설은 대사·장면과 원전의 구체적 연결이 새로운 이해를 주는지 검토한다. 이미 본문에서 설명한 사건을 질문으로 반복하는 항목은 덜어내고, 용어의 기본 뜻은 단어장에 둔다.
- [짧은 해설과 근거 연결](reading-views.md#keep-explanations-short-and-followable)을 적용한다.
  한 단서의 재미와 의미를 보통 2~3개의 짧은 문장으로 남기고, 확인한 원문 구절·도감/문서 항목·관련 장면으로 이어 준다.
  모든 항목에 같은 링크 수를 강제하지 않으며, 링크의 실제 본문·도착 위치와 해석의 근거 수준을 함께 확인한다.
  원문에서 해당 사실이 밝혀지는 시점 이전에 뒤의 답을 노출하지 않는다. 자료집 나열 순서·DB 번호·사건의 연대를 본편 공개 순서로 사용하지 않는다.
  최신 수정본을 보존한 뒤 필요한 부분만 고치고, 비공개 저장·미리보기와 공개 게시 상태를 따로 확인한다.
- 작품별 `reference_catalog.json`에서 질문에 맞는 출처를 고른다. 설정과 인과관계는
  게임 대사·퀘스트 원문을 우선하고, 나무위키의 장/막 문서와 인물 행적을 대조한다.
  앞 막의 공개 페이지는 독자가 이미 읽은 설명과 용어가 이어지는지 확인하는 데 쓴다.
  커뮤니티 해석은 보조 자료이며, 단독 해석을 확정된 사건으로 쓰지 않는다.
- 공개 본문 수집은 기존 [Argus](../../../docs/features/argus.md)를 사용한다.
  검색 발췌, 목차, 제목만 받은 응답은 본문 확인으로 세지 않는다. 요청한 절의 본문과
  경계를 확인하고 출처 URL·수집 시점·해시·근거 줄을 기존 source receipt에 남긴다.
- 최신 응답이 불완전하면 그 상태를 기록한다. 이전에 확보한 완전한 본문을 재사용한
  경우 그 사실과 수집 시점을 구분한다. 사이트 접근 거부를 다른 경로로 우회하지 않는다.
- 문장은 인물·행동·원인·결과가 드러나게 쓴다. 제목만 읽어도 무슨 사건인지 알 수
  있어야 한다. ‘2번 전투는 동행 뒤다’처럼 다른 번호의 내용을 알아야 이해할 수 있는
  제목, 작성 과정에 대한 설명, 근거 없는 강조를 피한다.
- 대사 속 추론은 ‘방랑자는 …라고 추측한다’처럼 주체를 밝힌다. 생각과 작품의 확정
  설정을 구분한다. 인용은 원문과 대조하고, OCR이 깨졌다면 확인한 부분만 바로잡는다.
- 본문과 독백이 같은 추론을 반복하면 본문에는 선택과 사건을, 독백에는 핵심 생각만
  남긴다. 긴 독백은 원문에서 짧게 발췌하고 전체 근거는 출처에 보존한다. 요약한 말을
  원문 인용처럼 따옴표 안에 넣지 않는다.
- 장면마다 누가 누구와 무엇을 했는지, 왜 다음 장면으로 이어지는지 확인한다. 죽음,
  존재의 소멸, 역할 대체, 다른 이야기로 이동한 상태를 하나로 합치지 않는다.
- 떡밥은 이미 회수된 상징과 아직 풀리지 않은 질문을 함께 다룬다. 인물의 주장을
  설정의 확정 사실로 바꾸거나, 이름이 없는 두 지칭을 근거 없이 같은 인물로 합치지
  않는다. `clues`에는 2~8개 항목을 둘 수 있으며 각 항목의 출처·확신 수준을 보존한다.
- 추측의 근거와 한계를 함께 적는다. 사건에 관한 단서를 무조건 ‘정체불명의 인물’로
  만들지 않는다. 단수·복수나 지시 대상이 모호하면 앞뒤 대사와 다른 언어판도 대조한다.
  커뮤니티 글은 발표 당시의 추측과 후속 막을 읽은 해석을 구분하고, 댓글의 정정도 확인한다.

## 2. 영상 순서와 사건의 관계를 따로 보여 준다

| 보기 | 독자가 하려는 일 | 번호와 순서 |
| --- | --- | --- |
| 영상 따라보기 | 방송을 보며 현재 장면을 이해한다 | 기존 장면 번호·ID·공개 순서를 보존한다. 다시보기 입력 번호는 이 번호다. |
| 세계선·인과 지도 | 장면이 속한 이야기와 앞뒤 영향을 정리한다 | 별도의 ‘정리’ 번호를 쓰고 본편으로 돌아가는 링크를 붙인다. |

- 회상·먼저 공개된 단편·다음 이야기·현실 귀환은 필요한 장면에서 짧게 알린다.
  번호 순서가 사건의 시간순으로 오인되지 않게 한다.
- 기본 영상 따라보기에서도 시점이 바뀌는 장면의 제목 위에 전환 안내를 둔다.
  ‘시점 전환 · 카르티시아’, ‘과거 회상 · 미아’, ‘회상을 마친 뒤 · 루파’처럼
  **전환의 종류와 따라갈 인물**을 먼저 쓰고, 어디에서 어디로 옮겨가는지 한 문장으로
  설명한다. 회상 진입뿐 아니라 복귀, 교차 장면, 꿈과 그 뒤의 복귀도 짝지어 확인한다.
  같은 흐름이 계속되는 장면에는 같은 안내를 반복하지 않는다.
- 카메라가 다른 인물을 비추는 것과 인물이 다른 이야기로 이동하는 것을 구분한다.
  방랑자가 남은 장면 뒤에 루파의 다음 이야기가 나오는 경우, 둘을 따로 표시한다.
  초반에 앞뒤 관계가 감춰져 있다면 미확정 상태를 보존하고 후반의 정답을 안내에
  앞당겨 넣지 않는다. ‘현재’나 ‘현실’은 소노라와 현실을 혼동시키지 않게 쓴다.
- 전환 안내는 원래 장면 카드 안에 두어 스포일러 가림, 사진 보기의 장면 상세,
  원래 번호와 다시보기 연결을 함께 보존한다. 별도 번호가 붙는 사건으로 만들지 않는다.
- 여러 이야기를 무조건 하나의 시간순으로 압축하지 않는다. 각 이야기 안의 진행,
  이야기 사이에 남긴 영향, 인물의 이동을 구분하고 선의 의미를 범례로 설명한다.
- 근거 없는 세계선 총수, 회차 번호, 날짜나 동시각을 만들지 않는다. 같은 높이의
  배치는 동시 발생을 뜻하지 않는다. 불명확한 경계는 불명확하다고 쓴다.
- 기본 보기 이름은 읽는 목적을 설명한다. 요청하지 않은 ‘결말 포함’ 안내를 반복하지 않는다.
  기존 스포일러 가림과 공개 범위는 보존하고, 필요한 개별 안내만 선택적으로 붙인다.
  본편에서는 앞뒤 순서가 헷갈리는 회상, 서로 다른 이야기의 교차, 이야기 간 이동과
  합류를 확인할 필요가 큰 장면에만 지도 링크를 둔다. 단순 과거 설명이나 같은 이야기의
  연속 장면에는 반복하지 않는다. 링크와 스포일러 안내는 기존 카드 본문 안에 두고,
  번호·제목·기존 링크처럼 중앙선 방향으로 정렬한다. 왼쪽 카드는 오른쪽 정렬,
  오른쪽 카드는 왼쪽 정렬이다. 카드 안에서 가운데 정렬하거나 중앙선 위로 꺼내지 않는다.
  모바일과 사진 상세에서는 기존 본문 정렬을 따른다. 본문 안에 두어 장면의 스포일러
  가림과 키보드 진입 제한도 함께 적용받게 한다.
  글꼴·굵기·색·간격은 기존 장면 이동 링크 스타일을 재사용한다. 밑줄은 링크 제목에만
  적용하고 스포일러 안내까지 이어지지 않게 한다.
  지도에서는 관련된 원래 장면 번호로 돌아갈 수 있어야 한다. 링크를 줄여도 시점 전환
  안내는 독립적으로 유지한다.
- 미래에 추가될 방송 입력의 기준이 흔들리지 않도록 본편 장면을 임의로 재번호하지 않는다.
  하이라이트는 본편 번호와 분리한다.

## 3. 용어와 앞 막 연결을 확인한다

- 용어 설명은 해당 장면을 이해하는 데 필요한 범위로 쓴다. 등장인물의 가설을 일반
  법칙으로 확대하지 않는다. 근거 출처와 필요시 공개 시점을 함께 보존한다.
- 본문에서 용어 사전으로 간 뒤 읽던 장면으로 돌아오는지 확인한다.
- Elio 본문 외부 링크는 `[[4막|https://ttaem.com/storytimeline/wutheringwaves/ch2-act4/]]의`
  형식을 쓴다. Markdown 링크를 본문 필드에 섞거나 조사를 URL 안에 넣지 않는다.
- 이미지 출처와 방송 이동 시점은 독립된 근거다. 캡처용 영상이 있다는 이유만으로
  그 영상을 독자의 다시보기 링크로 노출하지 않는다.
- 핵심 컷신과 같이보기 하이라이트는 대표 이미지를 기본으로 준비한다. 같은 논리적
  하이라이트의 여러 방송 연결은 한 이미지를 공유하며, 일반 본편 장면 모두를 새
  하이라이트나 필수 이미지 대상으로 승격하지 않는다. 기존 선택 이미지와 관리자
  수정은 보존하고 이미지가 없는 항목만 후보로 보완한다.
- [공통 이미지 선택 기준](reading-views.md#select-storyboard-images-with-verified-pixels)을 적용한다.
  stable·외부 작성 환경에서도 원본 URL을 기본 입력으로 삼고, 제공된 storyboard와 검증된
  VODMatch 캐시를 먼저 재사용한다. 조회·원격 격자 crop 표시·다운로드·영구 보관은 구분한다.
  핵심 컷 자체가 실제 픽셀에 보이는지와 주변 순서를 확인하며, 짧은 컷 누락·낮은 화질은 더 좋은 제공 규격을
  먼저 살피고 부족한 한 구간만 좁게 추출한다. 기존 세 프레임 우선·최대 13장·360p·전체
  60초 예산을 유지한다. 같은 사건의 행동·감정·구도를 고르고 후행 결말이나 다른 사건은
  반려한다. 게임 캐릭터의 얼굴은 정상이며 방송자 얼굴·아바타·webcam·채팅 overlay는 반려한다.
  특정 작품의 K tube 영상을 다른 작품의 기본 출처로 고정하거나 방송 시계를 이미지 시계로
  대신 쓰지 않는다. 실제 컷을 판단하지 못하면 비공개 검토와 미확인 범위를 남긴다.
- 서명된 storyboard URL은 관측 주소로 기록한다. 만료·변경 시 명시적으로 고른 기존 그룹만
  같은 영상 ID·이미지 시각의 최신 tile mapping으로 정상 수리 1회를 시도한다. 평상시 갱신은
  기존 선택을 보존한다. 실패해도 본문·seek를 유지하고 전체 영상 확장이나 무한 재시도를 하지 않는다.
- 장기 보존·crop 보정·로컬 픽셀이 필요한 export는 검토한 최종 선택만 기존 관리형 이미지로
  저장한다. 기존 원격 선택의 보존은 같은 원본 URL·crop의 기록된 pixel hash 일치가 필요하며,
  읽기 실패나 불일치가 나면 기존 선택과 검토 필요 상태를 남긴다. 원격 표시는 CORS가 필요한
  canvas/export 지원이나 영구 보관을 보장하지 않는다.
  일반 export 기능이나 새 proxy를 약속하지 않으며, 비공개 저장·미리보기를 공개 정적 URL 갱신으로
  보고하지 않는다. 선택·저장·공개의 실제 완료 상태를 각각 확인한다.

## 4. 사용자가 보낼 다시보기 형식

아래는 빈 양식이며, 대괄호와 `xx`는 실제 값이 아니다. 실제 방송이 여러 개면 URL별로
블록을 나눠 받는다. 긴 영상은 24시간을 넘는 시각도 시간·분·초로 해석한다.

```text
🌊 탬탬과 명조 스토리 이해하기
다시보기: [실제 URL]

1. [시각], [시각]
2. [시각], [시각]
3. [시각], [시각]

H1. [시각] [하이라이트 제목] / [장면 설명]

4. [시각]
```

- `1.` 등은 **영상 따라보기**의 장면 번호다. 지도 정리 번호와 혼용하지 않는다.
- 쉼표로 나열한 시각은 **각각 클릭하는 이동 지점**이다. 시작~끝 구간으로 바꾸지 않는다.
  종료점은 사용자가 구간이라고 명시했을 때만 넣는다.
- `H1`은 본편 장면과 별도로 놓이는 하이라이트다. 실제 제출된 목록에서 앞 장면과 다음
  장면 사이에 둔다. 위치가 따로 적혀 있으면 그 위치를 따른다. 위치가 모호하면 확인한다.
- **형식 예시에서 H1이 3번 다음에 있었다는 이유로 실제 3번 뒤에 하이라이트를 만들지 않는다.**
  예시의 ‘방랑자와 루파 전투’, 시각, 제목도 실제 장면이나 근거로 저장하지 않는다.
- 받지 않은 시각은 미입력 상태로 둔다. 다른 영상의 시각을 환산·추정하거나 누락을
  ‘장면 없음’으로 바꾸지 않는다. 부분 입력은 기존 검토 상태를 보존하며 이어 받는다.

### 기존 연결 데이터에 반영하는 방법

별도의 재생 링크 시스템을 만들지 않고 `elio.connections.v3`를 쓴다.

| 받은 값 | 기존 저장 위치 |
| --- | --- |
| 다시보기 URL과 방송자 | `streams[]`의 provider/video_id/channel_id/streamer_name |
| 번호별 이동 시각 | 번호를 고정된 event_id에 연결한 `links[]`의 각 `start_seconds` |
| 같은 번호의 추가 시각 | 같은 event_id·stream_id의 추가 link row, 별도 종료점 없음 |
| 실제 H1 제목·설명·위치 | `moments[]`의 title/summary/after_event_id, 적합한 kind |
| 하이라이트 방송 시각 | 해당 moment의 stream_id/start_seconds, 검토 근거 |

실제 확인된 행만 `verified`로 저장한다. 입력한 사용자 시점과 별도로 확인한 대사·영상의
근거를 정직하게 구분한다. 사용자 지정 시점이 곧 정확한 첫 프레임 검증을 뜻하지는 않는다.
플랫폼별 이동 URL은 기존 connections 함수가 만든다.

같은 방송의 단순 유튜브 재업로드는 [공용 VODMatch 분기](../../../docs/features/vodmatch.md#elio-같은-게임-장면-찾기)를
따른다. 같은 녹화본·중간 편집 없음이 확인되면 앞쪽 장면 하나로 시간 차이를 맞추고,
기존 장면·복수 시점·하이라이트·후기를 함께 환산한다. 같은 영상 쌍의 검토 근거는
막마다 다시 만들지 않으며, 환산 행을 새 개별 실측으로 표시하거나 모든 클립을 다시
받지 않는다. 실제 편집·합본 경계나 시각 충돌이 있을 때만 해당 구간을 더 확인한다.
기존 본문·이미지·장면 번호·플랫폼 보류·후기 위치를 유지하고 연결만 추가한다.

캡처용 영상의 기존 `hold`와 근거는 유지한다. provider hold는 영상별이 아니라 플랫폼별이므로,
새 YouTube 방송을 넣으면서 YouTube hold를 통째로 풀어 예전 캡처용 영상까지 노출하지 않는다.
필요하면 캡처용 연결은 원본/근거 사본에 보존하고, 독자용 connections에는 새 방송만 등록한다.
실제 방송을 활성화할 때는 `capture_only`와 활성 스트림을 동시에 두지 않는다.

## 5. 방송을 마친 뒤의 후기

감상·평가는 스토리 사실이나 문학 떡밥에 섞지 않고 템플릿의 별도 후기 영역에 둔다.
기존 `moments[]`와 다시보기 칩을 재사용한다. 후기 없는 페이지에는 빈 영역을 만들지 않는다.
후기 영역은 확인된 방송자 프로필과 제목으로 누구의 감상인지 먼저 보여 주고, 후기 범위와
재생 칩으로 이어진다. 프로필이 없으면 기존 이름 대체 표시를 쓴다. 짧은 감상 공간에는
배경·인용부호·타이포그래피로 분위기를 줄 수 있으며, 실제 발언처럼 보이는 문구나 별점은
근거 없이 만들지 않는다. 큰 패널 안에 큰 하이라이트 카드를 다시 넣거나 이동 목적을
반복 설명하지 않는다. `summary` 근거는 데이터에 보존한다. 좁은 화면에서는 버튼을 다음
줄로 배치하고 플랫폼 메뉴·멤버십 안내·키보드 포커스·스포일러 가리기를 실제로 확인한다.

비주얼 개선은 실제 콘텐츠가 있는 같은 화면 폭에서 전후를 비교한다. 검사 통과와 시각적
완성도는 별도로 확인하며, 최종 디자인을 정상 템플릿 빌드와 공개 후보에도 같은 모습으로
연결한다. 긴 문학 해설을 옮겼을 때도 빈 열·긴 세로 카드·중복 설명이 남는지 확인한다.

- `kind:"streamer_reaction"`, `placement:"streamer_review"`, `reviewer_name`은 방송자 이름이다.
  화면 제목은 `<reviewer_name>의 후기`다. 플랫폼/멤버십 표시는 기존 스트림 정보를 유지한다.
- `after_event_id`는 마지막 본편 장면 ID다. 후기를 본편 번호나 이야기 속 하이라이트로
  끼워 넣지 않는다. `title`은 사용자가 지정한 후기 범위, `summary`는 실제 확인한 발언만 쓴다.
  발언을 확인하지 않았다면 “이야기를 마친 뒤 나눈 감상을 들어본다”처럼 이동 목적만 설명한다.
- 같은 후기의 여러 플랫폼은 동일한 `moment_group_id`와 공통 제목·설명·방송자로 묶고,
  각 행에 `stream_id`, `start_seconds`, `verification`, `evidence_ref`를 따로 기록한다.
- 유튜브 대응은 같은 녹화본의 검토된 시간 차이와 컷 유무를 확인한다. 단순 재업로드의
  후기도 같은 시간 차이를 재사용하며, 후기 클립의 추가 검증을 일률적으로 요구하지 않는다.
  실제 편집 경계나 영상 길이 밖 시점은 보정하거나 플레이 링크를 보류한다.
  같은 방송 제목이나 마지막 본편 시각만으로 후기 시각까지 확인했다고 쓰지 않는다.

## 6. 게시 전 확인

1. 실제 URL·번호·시각·하이라이트의 대응을 검토한다. 1~29와 지도 번호를 섞지 않았는지,
   다중 시각이 별도 링크인지, 하이라이트가 한 번만 나오는지 확인한다.
2. 기존 source/story/media/connections와 layout 검증기를 실행한다. 캡처와 출처를 보존한다.
3. 최종 렌더에서 두 가지 보기, 범례, 회상 안내, 상호 이동, 용어 복귀와 모바일 화면을
   확인한다. 본문 링크와 영상 이동 링크의 실제 목적지를 확인한다.
4. 검토본에만 적용한 HTML 보정이 있다면 정상 게시 빌드에도 함께 반영되었는지 확인한다.
   JSON만 복사해 승인받은 보기 이름·범례·연결이 사라지는 후보를 게시하지 않는다.
5. 로컬 미리보기, 게시 후보, 실제 공개를 구분한다. 현재 요청이 ‘준비’라면 실제 입력을
   받을 수 있는 검토본까지만 만들고 예시 링크나 빈 하이라이트를 공개하지 않는다.

이 양식의 적용 사례는 issue #4037의 명조 2장 5·6막 검토본이다. 특정 등장인물·29개 장면·
13단계 지도는 그 작품의 데이터이며 다른 작품의 필수 개수나 고정 구조가 아니다.
